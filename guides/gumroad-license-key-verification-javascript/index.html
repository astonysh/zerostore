Gumroad License Key Verification in JavaScript

The endpoint, working Node code that handles refunds correctly, a proxy for browser apps, and the five things that break real integrations. Every example here runs against Gumroad's public license API — no access token, no SDK.

Checked against Gumroad's API documentation, October 2026.

Short version: POST https://api.gumroad.com/v2/licenses/verify with a form-encoded body containing license_key and product_id. No authentication is required. Check success in the response — then check purchase.refunded and purchase.chargebacked, because a refunded sale still returns success: true. Do not call it from a browser: the API sends no Access-Control-Allow-Origin header, so the request is blocked before it is sent. Use a small proxy.

The endpoint

ParameterRequiredDefaultWhat it does
license_keyYes—The key from the buyer's receipt
product_idRecommended—Your product's ID. May be required for products created after a certain date; product_permalink is an alternative
increment_uses_countNotrueBumps the license's use counter. Pass false for routine re-checks

A successful response looks like this — price is in cents, and the purchase object carries everything you need to make a decision:

{
  "success": true,
  "uses": 2,
  "purchase": {
    "email": "buyer@example.com",
    "product_name": "My App",
    "price": 2900,
    "currency": "usd",
    "quantity": 1,
    "order_number": 1234567,
    "license_key": "ABCD1234-EFGH5678-IJKL9012-MNOP3456",
    "refunded": false,
    "chargebacked": false,
    "subscription_cancelled_at": null,
    "subscription_ended_at": null,
    "subscription_failed_at": null
  }
}

Failures return success: false with a message — for example "That license does not exist for the provided product.", "This license key has been disabled." or "Access to the purchase associated with this license has expired."

Node: a verify function that gets it right

Node 18 and later has fetch built in, so this has no dependencies. The important part is not the request — it is what happens after it.

const GUMROAD_VERIFY = 'https://api.gumroad.com/v2/licenses/verify';

export async function verifyLicense(licenseKey, { productId, incrementUses = true } = {}) {
  const body = new URLSearchParams({
    license_key: licenseKey.trim(),
    increment_uses_count: String(incrementUses),
  });
  if (productId) body.set('product_id', productId);

  let res;
  try {
    res = await fetch(GUMROAD_VERIFY, {
      method: 'POST',
      headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
      body,
    });
  } catch (err) {
    // Network failure is NOT an invalid key. Say so and let the caller retry.
    return { valid: false, reason: 'offline', retryable: true };
  }

  const data = await res.json().catch(() => null);
  if (!data) return { valid: false, reason: `HTTP ${res.status}`, retryable: res.status >= 500 };
  if (!data.success) return { valid: false, reason: data.message || 'invalid', retryable: res.status >= 500 };

  const p = data.purchase || {};
  if (p.refunded) return { valid: false, reason: 'refunded' };
  if (p.chargebacked) return { valid: false, reason: 'chargeback' };
  if (p.subscription_ended_at || p.subscription_cancelled_at) {
    return { valid: false, reason: 'subscription ended' };
  }

  return { valid: true, uses: data.uses, email: p.email, purchase: p };
}

Usage:

const result = await verifyLicense('ABCD1234-EFGH5678-IJKL9012-MNOP3456', {
  productId: 'YOUR_PRODUCT_ID',
});
if (!result.valid) {
  console.error(result.retryable ? 'Could not reach Gumroad — try again' : `License rejected: ${result.reason}`);
}
The distinction that matters: retryable separates "we could not check" from "this key is bad". Collapsing the two — which a naive if (!data.success) invalid() does — tells paying customers their key is invalid every time their wifi drops. Check it before you ship.

Browser: you need a proxy, and here is one

If you call https://api.gumroad.com/v2/licenses/verify from page JavaScript, the request fails with:

Access to fetch at 'https://api.gumroad.com/v2/licenses/verify' from origin
'https://yourname.github.io' has been blocked by CORS policy: No
'Access-Control-Allow-Origin' header is present on the requested resource.

That is not a bug you can configure around — the API simply does not send the header, and your product page should not hold the credentials to call it anyway. Put a tiny proxy in front. This one deploys free on Cloudflare Workers and keeps your product_id server-side:

// worker.js — paste into the Cloudflare Workers editor, set PRODUCT_ID,
// ALLOWED_ORIGIN, then deploy. No npm, no build step.
const PRODUCT_ID = 'YOUR_PRODUCT_ID';
const ALLOWED_ORIGIN = 'https://yourname.github.io';
const CORS = {
  'Content-Type': 'application/json',
  'Access-Control-Allow-Origin': ALLOWED_ORIGIN,
  'Access-Control-Allow-Headers': 'Content-Type',
  'Access-Control-Allow-Methods': 'POST, OPTIONS',
  'Vary': 'Origin',
};

export default {
  async fetch(request) {
    if (request.method === 'OPTIONS') return new Response(null, { headers: CORS });
    if (request.method !== 'POST') return json({ valid: false, reason: 'method' }, 405);
    if (request.headers.get('Origin') !== ALLOWED_ORIGIN) return json({ valid: false, reason: 'forbidden' }, 403);

    let key;
    try { key = (await request.json()).license_key; } catch { key = null; }
    if (typeof key !== 'string' || !key.trim() || key.length > 128) {
      return json({ valid: false, reason: 'bad request' }, 400);
    }

    const res = await fetch('https://api.gumroad.com/v2/licenses/verify', {
      method: 'POST',
      headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
      body: new URLSearchParams({ license_key: key.trim(), product_id: PRODUCT_ID, increment_uses_count: 'true' }),
    });
    const data = await res.json().catch(() => null);
    const p = (data && data.purchase) || {};
    const valid = !!(data && data.success && !p.refunded && !p.chargebacked
                     && !p.subscription_ended_at && !p.subscription_cancelled_at);
    return json({
      valid,
      uses: data ? data.uses : undefined,
      reason: valid ? undefined : (data && data.message) || 'invalid',
    });
  },
};

function json(body, status = 200) {
  return new Response(JSON.stringify(body), { status, headers: CORS });
}

Then the browser side is four lines:

const VERIFY_URL = 'https://your-worker.your-name.workers.dev/verify';

async function verifyLicense(licenseKey) {
  try {
    const res = await fetch(VERIFY_URL, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ license_key: licenseKey }),
    });
    if (!res.ok) return { valid: false, retryable: res.status >= 500 };
    return res.json();
  } catch {
    return { valid: false, retryable: true };  // offline, not invalid
  }
}

The Origin check is deliberate but weak on its own — any client can send a fake header. It stops other websites from using your proxy as a free verification service; it is not authentication. If you need stronger guarantees, put the real gating behind a signed token the proxy issues, or gate the downloadable asset itself rather than the app's user interface.

Python, if your app is not JavaScript

import requests

GUMROAD_VERIFY = "https://api.gumroad.com/v2/licenses/verify"

def verify_license(license_key: str, product_id: str, increment: bool = True) -> dict:
    """{"valid": bool, "reason": str | None, "email": str | None}"""
    try:
        r = requests.post(GUMROAD_VERIFY, timeout=10, data={
            "license_key": license_key.strip(),
            "product_id": product_id,
            "increment_uses_count": "true" if increment else "false",
        })
    except requests.RequestException as exc:
        return {"valid": False, "reason": f"network: {exc}", "email": None}

    try:
        data = r.json()
    except ValueError:
        return {"valid": False, "reason": f"HTTP {r.status_code}", "email": None}

    if not data.get("success"):
        return {"valid": False, "reason": data.get("message", "invalid"), "email": None}

    p = data.get("purchase", {})
    if p.get("refunded") or p.get("chargebacked"):
        return {"valid": False, "reason": "refunded or charged back", "email": None}
    if p.get("subscription_ended_at") or p.get("subscription_cancelled_at"):
        return {"valid": False, "reason": "subscription ended", "email": None}
    return {"valid": True, "reason": None, "email": p.get("email")}

The five gotchas that break real integrations

  1. A refunded sale still validates. The API returns success: true with purchase.refunded: true. If you only check success, refunded customers keep full access forever. Check both flags, and the three subscription timestamps if you sell subscriptions.
  2. Browser calls fail with a CORS error. No Access-Control-Allow-Origin header is sent. Use a server or a proxy. This is the single most common reason people conclude "the API is broken".
  3. uses is global, not per device. It counts verifications made with incrementing enabled, across every machine the buyer owns. It is a rough telemetry signal, not DRM.
  4. increment_uses_count defaults to true. If you re-validate on every launch, you inflate the counter and burn through any usage limit you configured in Gumroad. Pass false for routine checks; increment once, on first activation.
  5. Offline users get locked out. A pure online check fails closed, which is safe and hostile at the same time. Cache the last successful verification locally with an expiry — a 7- to 30-day grace period is the usual compromise — and re-verify when the network returns.
One more: if you omit product_id for a product that requires it, Gumroad returns HTTP 500, not 400 — with the message that product_id is required. Do not let a generic "500 means try again" path or a "500 means invalid" path swallow it; log the message.

Getting a real key to test with

You cannot test activation without a purchase. The fastest legitimate way: create a 100%-off discount code in your Gumroad product, buy your own product with it, and use the key from the receipt email. Then delete the code. This gives you a real key, a real purchase object and a real refund path to test against — and you can refund yourself afterwards to watch the refunded flag do its job.

Questions people actually ask

How do I verify a Gumroad license key in JavaScript?

POST form-encoded to https://api.gumroad.com/v2/licenses/verify with license_key and product_id. No token required. Check success, then refunded and chargebacked.

Why do I get a CORS error in the browser?

The API sends no Access-Control-Allow-Origin header. Route the call through your own server or a Cloudflare Worker proxy — code above.

Do refunded purchases still validate?

Yes, unless you check purchase.refunded or purchase.chargebacked. Treat either as invalid.

Is there a separate endpoint to increment uses?

No. Usage counting happens on the verify call itself via increment_uses_count, which defaults to true.

What is my product ID?

Open the product in Gumroad and look at the license-key or content section — it is shown alongside the license key settings. Keep it in the proxy, not in page JavaScript.

Do Lemon Squeezy and Payhip have this too?

Yes, both issue license keys via their own APIs. The shape of the problem is identical: verify server-side, handle refunds explicitly, and distinguish "invalid" from "unreachable".
