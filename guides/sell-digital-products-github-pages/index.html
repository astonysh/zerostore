How to Sell Digital Products from GitHub Pages

You can host a real product page on GitHub for $0 and never touch a server. You cannot take a payment there — and knowing exactly where that line is shapes every design decision. Here is the whole thing, including the hosting rules that pages like this one usually leave out.

Limits and platform terms checked October 2026.

The short version: GitHub Pages serves static files only — no server-side code, no secrets, no card processing. So the pattern is page on Pages, checkout on a merchant-of-record platform (Gumroad, Lemon Squeezy or Payhip). That platform takes the payment, delivers the file, and handles sales tax and VAT. Hosting costs $0; the platform takes a percentage per sale; a custom domain is optional at about $10–15/year.

What static hosting can and cannot do

Verify a license key at runtime✗ Not directlyA proxy you run (Cloudflare Worker, Vercel function) or the platform's overlay

That last row is the one people get wrong. Putting product.zip in a public repository and selling "access" to it means anyone who finds the repo can download it for free. Sell through the platform's delivery, not through your own repository.

The walkthrough

  1. Create the repository and turn on Pages

    Create a GitHub repository, push your files to main, then go to Settings → Pages → Build and deployment → Source: GitHub Actions. If you would rather GitHub build from a branch, choose that instead — the trade-off is in the limits section below.

    Add an empty .nojekyll file at the repository root if you are serving files straight from a branch. It stops GitHub's Jekyll processor from ignoring directories that start with an underscore.

  2. Get a storefront template — or write one file

    A product page needs very little: a headline, what the product is, who it is for, the price, an FAQ and a buy button. The ZeroStore kit is a single-file version of that, MIT licensed:

    npx degit astonysh/zerostore/kit my-store
cd my-store
node scripts/build.mjs   # preview: open dist/index.html

    Or write your own index.html. One file, inline CSS, no framework. It will load in well under a second and there is nothing to break.

  3. Set up the checkout before you set up the page

    Pick one platform and create the product there first, so you have a real checkout URL to point at. Gumroad and Payhip start you selling immediately; Lemon Squeezy puts new stores through a short review before live payments. Full instructions are in the kit's docs/payment-setup.md.

    Then the only thing the page needs is that URL:

    {
  "CHECKOUT_URL": "https://yourname.gumroad.com/l/my-product",
  "checkout_provider": "gumroad"
}

    gumroad and lemonsqueezy open the checkout as an overlay on your page; payhip and link send the buyer to the platform's own page.

  4. Deploy with a GitHub Actions workflow

    The kit ships a workflow that builds the page and publishes it on every push:

    on:
  push:
    branches: [main]
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: node scripts/build.mjs
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with: { path: dist }
      - uses: actions/deploy-pages@v4

    Push to main and the site is live at https://yourname.github.io/my-store/ in under a minute. Using Actions also sidesteps the 10-builds-per-hour limit that applies to branch-based builds.

  5. Add a custom domain (optional)

    Buy a domain, add a CNAME record pointing at yourname.github.io, put a file named CNAME containing your bare domain at the root of what you publish, and tick Enforce HTTPS in the Pages settings. Nothing else changes — and if you skip it, yourname.github.io/repo is a perfectly serviceable address.

  6. Do the SEO basics once, properly

    These are the things that decide whether search engines can index you at all:

    • A unique <title> and meta description — what you sell, in the words a buyer would type.
    • A canonical link to the exact URL: <link rel="canonical" href="https://yourname.github.io/my-store/">.
    • Open Graph tags so the link previews correctly when someone shares it.
    • JSON-LD product data — name, price, currency — so search engines understand what the page is.
    • sitemap.xml and robots.txt at the site root, with the sitemap referenced from robots.txt. The kit's build script writes both.

    Then submit the sitemap in Google Search Console. Indexing takes days to weeks; there is nothing to tune in the meantime.

Be honest about the last line. A storefront has never sold anything on its own. GitHub Pages removes your hosting bill, not your need for visitors. Budget for either content that earns search traffic over months, or a community you already belong to — and expect the first month to be quiet either way.

GitHub Pages limits you should know before you commit

  • 1 GB published site, and a recommended 1 GB maximum for the source repository.
  • 100 GB of bandwidth per month as a soft limit. A text-and-screenshot product page uses a rounding error of that.
  • 10 builds per hour soft limit for branch-based builds — not applied when you publish with a custom GitHub Actions workflow.
  • Deployments time out after 10 minutes, and only one user or organisation site is allowed per account (project sites like yourname.github.io/repo are unlimited).
  • GitHub's documentation states Pages is not intended as free hosting to run an online business, an e-commerce site or a SaaS. Read that clause yourself before you build on it. A static page whose buy button links out to a checkout hosted elsewhere is a very common pattern, but it is your call — and if you want zero ambiguity, the same static files run unchanged on Cloudflare Pages or Netlify's free tier.

The limits are soft: GitHub's usual response to a site that exceeds them is to contact the owner and suggest a CDN or another host, not to silently delete your work. Still, treat Pages as excellent free hosting for a marketing site rather than as infrastructure you would bet a business on without a plan B. Keeping the storefront portable is cheap insurance — which is why a template that is just static HTML is worth more than one that depends on a build service.

Questions people actually ask

Can I sell digital products from GitHub Pages?

Yes, with a hosted checkout. Pages hosts the page; Gumroad, Lemon Squeezy or Payhip takes the money and delivers the file.

Can I keep my repository private?

For a storefront, probably not on the free plan — GitHub Pages from a private repository requires GitHub Pro or above. Since a product page is public by definition, a public repository costs you nothing but means never committing secrets or the product file itself.

How do I take payments from a static page?

You link to a hosted checkout. Gumroad and Lemon Squeezy also offer a JavaScript overlay so the buyer never leaves your page, but the card details go to their servers, not yours. See the platform fee calculator for what each takes.

Can I add license keys to a static storefront?

You can display and store them, but you cannot verify one safely in the browser — a static page cannot hold an API secret, and the license API does not allow direct browser calls. The usual fix is a small proxy function on Cloudflare Workers or Vercel that holds the secret. More in the Gumroad license key guide.

What about analytics?

Use a privacy-friendly counter such as GoatCounter or Plausible. Google Analytics works but adds a third-party script and a consent question; for a one-page storefront it is usually more than you need.
